Agent 智能文件管理助手

自然语言交互 · 全文检索 · RAG 增强问答
Agent Python FastAPI DeepSeek API Whoosh RAG Chardet JavaScript
项目概述

本地文件管理长期依赖手动操作与固定目录检索，查找文件内容需逐个打开预览，效率低下；非技术用户更难以通过命令行或复杂检索语法完成个性化查询。本方案面向本地文件智能管理需求，构建了一个支持自然语言交互的文件管理 Agent。用户只需用自然语言下达指令，即可完成文件的创建、删除、修改、按类型列出、内容读取，以及基于文件内容的智能检索与问答。系统以 FastAPI 提供后端异步服务，Whoosh 构建全文索引，DeepSeek API 负责指令解析与答案生成，前端以对话式界面实现全流程交互，有效降低文件管理门槛，提升检索与操作效率。

关键技术介绍
1. 大语言模型 Agent（LLM Agent）

Agent 是当前人工智能领域的重要范式，其核心思想是让大语言模型（LLM）作为"大脑"，通过工具调用（Tool Use）与外部环境交互，从而完成复杂的多步骤任务。与传统的固定流程程序不同，Agent 具备理解自然语言、规划任务步骤、选择合适工具、处理异常反馈的能力。本系统中，DeepSeek API 充当 Agent 的推理核心，接收用户自然语言指令后，输出结构化的 JSON 操作意图（包含 action、mode、path、content、query 等字段），后端再根据意图调度对应的文件操作或检索模块。这种设计使得用户无需学习任何命令语法，即可完成复杂的文件管理任务。

图1：LLM Agent 的"解析—调度—执行"闭环流程
2. FastAPI

FastAPI 是一个基于 Python 3.6+ 的现代高性能 Web 框架，底层基于 Starlette（异步 Web 框架）与 Pydantic（数据校验库）。其核心优势在于：原生支持异步请求处理（async/await）、自动生成 OpenAPI 文档、基于类型注解的请求参数校验，以及极高的运行效率。本系统采用 FastAPI 搭建后端服务，对外暴露 /chat（自然语言指令入口）、/files（文件列表接口）等端点。借助 Pydantic 的 BaseModel 定义请求体结构，确保前后端数据交换的类型安全。FastAPI 的异步特性也能在调用 DeepSeek API 或执行全文检索时避免阻塞，提升响应速度。

图2：FastAPI 异步请求处理与 Pydantic 数据校验机制
3. Whoosh 全文检索

Whoosh 是一个纯 Python 实现的轻量级全文检索库，无需依赖外部服务即可在本地建立倒排索引。其核心组件包括 Schema（定义索引字段）、IndexWriter（写入索引）、Searcher（执行查询）与 QueryParser（解析查询语法）。Whoosh 支持多字段检索、布尔查询、模糊匹配、短语查询以及按时间、数值范围过滤等能力。本系统中，Whoosh 被用于对 D:/Manage 目录下的文本文件建立索引，索引字段包含文件路径、文件名、文件内容、大小与修改时间。检索时通过 MultifieldParser 同时在文件名与内容中搜索，快速定位包含关键词的文件，为 RAG 提供召回源。

图3：Whoosh 倒排索引与多字段检索结构
4. RAG（Retrieval-Augmented Generation）

RAG 即"检索增强生成"，是一种将信息检索与大语言模型生成能力结合的技术范式。其基本流程为：先根据用户问题从知识库（本系统为本地文件）中检索出相关内容片段，再将片段作为上下文注入 LLM 的提示词中，由 LLM 基于真实上下文生成答案。相比纯生成模式，RAG 能有效缓解模型幻觉、突破训练数据时效限制，并支持私有数据的问答。本系统采用轻量级 RAG 方案：由 Whoosh 检索出最相关的 3 个文件，读取其内容片段（每个文件截取前 1500 字符）拼接为上下文，最终调用 DeepSeek 生成用户问题的答案。整个过程只读文件、不修改，确保安全。

图4：RAG 的"检索 → 增强 → 生成"三阶段流程
5. Chardet 编码检测

在处理本地文件时，编码问题是绕不开的难题。同一份文本可能以 UTF-8、GBK、GB2312、Big5 等不同编码保存，若统一按 UTF-8 读取会出现乱码或异常。Chardet 是一个成熟的 Python 字符编码检测库，通过统计字节序列的分布特征，推测文本最可能的编码格式。本系统在读取文件内容前，先使用 chardet.detect() 检测编码，再以检测结果解码文本，并配合 errors='ignore' 容错处理，确保不同编码的文件都能被正确索引与检索。

核心问题与解决方案

在初步方案中，系统仅依靠 LLM 直接生成回答，缺乏对本地文件的真实访问能力，模型容易产生"幻觉"，即编造并不存在的文件内容。同时，用户"列出所有 Python 文件"这类精确操作指令，也无法由纯生成模型准确完成。

针对上述问题，本方案采用Agent 意图解析 + 多模式调度策略：由 DeepSeek 先解析用户指令，输出结构化的意图（区分 create / delete / modify / ask 动作，并在 ask 下进一步区分 list / read / query 三种模式），后端再根据意图路由到不同的处理逻辑。list 模式直接扫描目录返回文件列表，read 模式直接读取指定文件全文，query 模式则走 RAG 检索 + 生成。同时，所有文件操作均被限定在 BASE_DIR 根目录下（通过 safe_path 校验），有效防止路径越界。该方案在保证指令执行准确性的同时，显著降低了模型幻觉带来的风险。

技术实现流程
  1. 环境与目录配置：设定文件管理根目录 BASE_DIR（如 D:/Manage），并配置 DeepSeek API Key 环境变量，初始化 OpenAI 兼容客户端。
  2. 索引构建：启动时递归扫描根目录下的文本文件，通过扩展名白名单与 Chardet 编码检测过滤可索引文件，将路径、文件名、内容、大小、修改时间写入 Whoosh 索引。
  3. 自然语言解析：用户在前端输入指令后，后端调用 DeepSeek API，将自然语言解析为包含 action、mode、path、query 等字段的结构化 JSON。
  4. 意图路由与执行：根据解析结果路由到对应模块——create/delete/modify 走文件操作，ask/list 走目录扫描，ask/read 走文件读取，ask/query 走 RAG 检索与生成。
  5. 结果返回与展示：将执行结果（操作状态、文件列表、文件内容或 AI 答案）以 JSON 返回前端，前端在对话界面中渲染为对应的消息卡片。
核心代码

以下为 Agent 意图解析、路径安全校验与 RAG 生成的核心代码片段：

# 路径安全校验：所有操作限定在 BASE_DIR 内 def safe_path(rel_path: str) -> Path: if not rel_path: return BASE_DIR target = (BASE_DIR / rel_path).resolve() if not str(target).startswith(str(BASE_DIR.resolve())): raise PermissionError("禁止访问根目录之外的文件") return target # Agent 意图解析：调用 DeepSeek 输出结构化指令 def parse_with_deepseek(user_message: str): system_prompt = """你是一个文件管理助手。根据用户指令，返回 JSON： - action: create / delete / modify / ask - mode (仅 ask): list / read / query - path / content / query / filetype""" response = client.chat.completions.create( model="deepseek-chat", messages=[ {"role": "system", "content": system_prompt}, {"role": "user", "content": user_message} ], temperature=0.1, max_tokens=300 ) return json.loads(response.choices[0].message.content) # RAG 生成：检索 → 构建上下文 → 调用 LLM def rag_answer(question, query_for_search=None, filetype=None): hits = search_files(query_for_search or question, filetype, limit=3) if not hits: return "未找到相关文件，无法回答。" context = "\n".join( f"【{h['filename']}】\n{read_file_content(Path(h['path']), 1500)}" for h in hits ) # 将 context 注入提示词，调用 DeepSeek 生成最终答案

技术栈
  • Agent 框架：DeepSeek API（Function Calling / JSON 结构化输出）
  • 后端服务：Python 3.10 + FastAPI + Uvicorn
  • 全文检索：Whoosh（倒排索引 + MultifieldParser 多字段查询）
  • RAG 方案：检索增强生成（Whoosh 召回 + DeepSeek 生成）
  • 编码检测：Chardet 自动识别文件编码
  • 数据校验：Pydantic BaseModel 请求体校验
  • 前端交互：HTML5 + CSS3 + 原生 JavaScript（Fetch API 异步通信）
